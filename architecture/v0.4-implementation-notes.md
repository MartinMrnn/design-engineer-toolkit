# v0.4 · Implementation notes: where the build differs from the spec

The spec (`v0.4-creative-process.md`, approved at c089065) is not edited after approval. This file records each place where the implementation differs from it, or completes it, and how each was settled. Lots 1 and 2 only.

Kinds: **functional** (what an agent, the lead or the user does changes) or **organisation** (where a file lives, how a rule is worded; nothing changes in what is done).

| # | Spec | Implementation | Kind | Settled |
|---|---|---|---|---|
| 1 | §5: C1 runs alongside B1 and before B2; §13.1 does not list `contract.json` among the files of lot 1 | The contract's step order is `A1, B1, C1, B2, …` (`charter.py check` computes what is due from it) | organisation: the order is the one §5 sets; only the file list of §13.1 missed it | 7b56782; nothing more to do |
| 2 | §6.2: a specimen's folder holds its captures, grey and blurred included | `views.js` writes them to `design/reviews/captures/` (`design-specimens-<id>-index-<viewport>-<view>.png`), the folder `kickoff.py` fixes for the critic's scripts | organisation: names carry the specimen's id, nothing is lost or overwritten | 2b31b5b; `steps.md` names the folder |
| 3 | §6.1: the critic reviews the cards for distinctness; nothing says what follows | The critic gives each card a verdict, keep, rework or replace (generic: a competitor could use it unchanged), with a hue-swap test for variants. A card marked rework or replace goes back to the art director once, before any specimen: reworked, replaced, or dropped when no relevant idea is left (three specimens then). The specimens also take the critic's review as input | functional: it applies §8's table (a weak idea is not deepened) at the cheapest point, before a specimen is spent on it | b9b88b1, 05642b5 |
| 4 | §8: in phase 1 "the mission gives only the preview links" | Until 05642b5, the phase 1 mission also gave the charter (brief and `07-visual-intent.md`, which lists the ideas) and, at round 1, `design/specimens/` (each `idea.md`). Now phase 1 gets the preview links only and opens nothing else; the references, the check and the taste file come with phase 2 | functional: the blind reading was blind by instruction only, with the ideas within reach | 05642b5 |
| 5 | §8: "two phases, with a lock" | The lock was a rule ("never rewrite"). Now the lead copies the report to `…-blind.md` when phase 1 is written, and compares the `Blind reading` lines after phase 2; a difference is reported to the user and the review counts as not blind | functional: the lock can be checked | 05642b5 |
| 6 | §8: the two judgements, the gap between the page and its card as evidence | The report has an `Intent` line (claimed by the card, perceived blind, the gap) and an `Execution` line next to `Idea` | functional: the claimed and perceived intent, and the idea and its execution, each have their own line | 05642b5 |
| 7 | §13.1: experimental axe rules and "incomplete" results are reported as needs review | As specified (`checks.js`, `review` list). Listed here only because an earlier note called it a deviation | none | cc42c14 |
